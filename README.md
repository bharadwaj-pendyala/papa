# 📖 Papa

### Hemingway-style readability linting for Markdown and text.

Papa flags hard sentences, passive voice, adverbs, and complex phrasing with a
readability grade. It is an open-source **alpha** CLI and Python library that
can run locally or in CI, emit JSON for automation, and generate a self-contained
HTML report.

## Status

Papa is currently **alpha software**. The supported surface is intentionally
small:

- CLI command: `papa`
- Python package: `papa-lint`
- Input formats: Markdown and plain text
- Reports: terminal, JSON, and self-contained HTML
- CI gating: use `--max-grade` and the process exit code

GitHub Action packaging, SARIF/Markdown reporters, config files, optional
external linters, and built-in LLM rewriting are roadmap items.

## Why Papa?

The [Hemingway Editor](https://hemingwayapp.com) is useful, but it is closed,
manual, and not designed for docs pipelines. Other open-source writing tools
exist, but they tend to have separate output formats and workflows.

Papa focuses on a narrow first job: make prose readability checks scriptable.

- **Scores readability** with ARI, Flesch-Kincaid, and Gunning fog.
- **Highlights like Hemingway** by marking hard sentences, passive voice,
  adverbs, and complex phrases.
- **Handles Markdown safely** by ignoring frontmatter, fenced code, inline code,
  and SVG while preserving offsets back to the original file.
- **Emits JSON** so agents, scripts, or dashboards can consume the findings.
- **Gates CI** by exiting non-zero when prose is harder than your max grade.

## ⚡ Quickstart

```bash
pipx install papa-lint

papa post.md
papa post.md --report html -o report.html
papa post.md --report json > findings.json
papa post.md --max-grade 10
```

Example terminal output:

```text
post.md  -  Grade 11, hard to read
  ✗ fails --max-grade 10

  18 hard · 4 very hard · 6 passive · 9 adverbs · 12 complex
  ARI 11.2 · FK 10.8 · Fog 12.1  (142 sentences)

  L42   very hard  Very hard to read (grade 16): "Because the detour squeezes..."
  L58   passive    Passive voice: 'is measured'
```

## 🧪 CI usage

Papa does not need a dedicated GitHub Action yet. Install it in your workflow
and let `--max-grade` fail the job when prose crosses your threshold:

```yaml
name: readability
on: pull_request
jobs:
  papa:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: python -m pip install papa-lint
      - run: papa README.md docs/*.md --max-grade 10
```

For local development, run the same command before opening a PR.

## Exit codes

| Code | Meaning |
| ---- | ------- |
| `0` | Every file passed, or no `--max-grade` was set. |
| `1` | A file is harder than `--max-grade`, or has no prose and `--fail-on-empty` is set. |
| `2` | Usage or file error: a bad option, or a missing or unreadable file. |
| `3` | Internal error in Papa. Set `PAPA_DEBUG=1` to print the traceback. |

A file with no prose to grade (empty, or only headings, code, or frontmatter;
no sentence of 4 or more words) reports "No prose found" and gets the JSON
verdict `"skip"`. It does not fail `--max-grade` unless you pass
`--fail-on-empty`.

## 🤖 LLM workflow

Papa does not call an LLM directly. It emits structured JSON that you can hand to
an agent or script:

```bash
papa post.md --report json > findings.json
```

The JSON includes the file path, document score, and findings with offsets into
the original source:

```jsonc
{
  "version": "0.1",
  "file": "post.md",
  "score": {
    "ari": 11.2,
    "flesch_kincaid": 10.8,
    "gunning_fog": 12.1,
    "reading_grade": "Grade 11, hard to read",
    "verdict": "fail"
  },
  "findings": [
    {
      "start": 1423,
      "end": 1490,
      "category": "passive",
      "message": "Passive voice: 'is measured'",
      "severity": "warn"
    }
  ]
}
```

See [docs/llm-contract.md](docs/llm-contract.md) for a prompt pattern that uses
Papa findings to guide a rewrite.

## 🔍 How it works

```text
input -> Ingestor -> Analyzers -> Aggregator -> Reporters
         strip code  readability  merge spans  terminal
         + SVG       passive      + scores     json
         offset map  adverbs                  html
                     complex phrase
```

1. **Ingest**: detect Markdown or text, strip non-prose, and preserve an offset
   map back to the original source.
2. **Analyze**: run built-in analyzers for readability, passive voice, adverbs,
   and complex phrases.
3. **Aggregate**: merge overlapping findings, compute document scores, and apply
   the optional max-grade gate.
4. **Report**: render terminal, JSON, or HTML output and set the exit code.

## Python API

```python
from papa import analyze

result = analyze(open("post.md", encoding="utf-8").read(), path="post.md", max_grade=10)
print(result.score.reading_grade)
print(result.score.verdict)
```
